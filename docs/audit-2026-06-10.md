# Heber Repository Audit — 2026-06-10

Principal-level technical audit. Analysis only — no code was modified. All findings cite file:line and are labeled **[fact]** (verified in code) or **[judgment]** (assessment). Findings from prior audit documents were re-verified against the current tree; several turned out to be stale and are called out as such.

---

## 1. Executive Summary

**Overall health grade: B.** Heber's core data path — Redis Streams consumer → Bronze JSONL.gz → Silver Parquet → Gold features, read back through `HeberReader` — is genuinely well-engineered: flush-before-ACK durability, a disk-first DLQ, predicate pushdown, and an enforced zero-leakage invariant on Gold writes. The grade is held back not by the code that runs, but by the code that doesn't: a large halo of aspirational subsystems (Iceberg, lakeFS, Karapace, Kubernetes, Terraform, a dead CI deploy pipeline) that adds dependency weight and cognitive load without being wired into the data path, plus quality gates (mypy, bandit) that exist but are switched off, and a 1,856-test suite whose breadth masks thin coverage of the highest-value logic.

**Top 3 risks:** (1) The catalog API binds `0.0.0.0` with zero authentication while a complete, unused access-control module sits beside it; (2) the consumer's Bloom-filter deduplication, with no backing store wired in, silently drops legitimate events on false positives — invisible data loss in a system whose whole purpose is data fidelity; (3) live credentials (Discord webhook, gateway API key) sit in the local `.env`, one CI/CD copy-paste away from leaking.

**Top 3 opportunities:** (1) Prune or explicitly shelve the aspirational layer — this is the single highest-leverage cleanup; (2) deepen tests on the money path (reader, normalizer coercion, triple-barrier labels) instead of adding more contract tests; (3) re-enable the dormant quality gates incrementally so the strong engineering culture visible in the core gets enforced mechanically.

## 2. Repo Map

**Purpose.** Heber is the data lakehouse of the Empire algo-trading monorepo: it ingests normalized market events from Data-Gateway via Redis Streams, persists them through Bronze (raw JSONL.gz) → Silver (typed Parquet) → Gold (ML features/labels) layers on `/Volumes/heber/data`, and serves them back to trading systems via the `HeberReader` filesystem reader and a Postgres-backed catalog API.

**Stack.** Python 3.12, uv, Pydantic v2, FastAPI, SQLAlchemy 2 (async, asyncpg), pyarrow/pandas, redis-py asyncio, structlog + Prometheus, Feast, exchange-calendars. Declared but not in the live data path: pyiceberg, lakefs, soda-core-duckdb, python-schema-registry-client ([pyproject.toml:31-44](../pyproject.toml)).

**Maturity.** A production system for one user, operated on a single Mac: docker-compose (14 services) + 5 launchd plists ([launchd/](../launchd)) are the real deployment. The K8s manifests, Terraform modules, and CI deploy stages are templates that have never run (verified: no `.terraform/`, deploy jobs gated on a branch that doesn't exist — see F-7).

**Architecture sketch.**

```
Data-Gateway → Redis Stream (heber:events)
  → EventConsumer (writer/consumer.py)          ← dedupe, validate, retry, DLQ
      → BronzeWriter (JSONL.gz, append-only)
      → SilverWriter (typed Parquet, Arrow schemas)
  flow_alerts → watch/ (consumer→poller→features→writer)  ← alert enrichment
  EOD → gold_poller/ → features/pipelines/ (~18 pipelines) → Gold Parquet
  Readers: HeberReader (reader/core.py)          ← predicate pushdown, asof
  Metadata: catalog/ (FastAPI :8085 + Postgres)
```

**Key directories** (`heber/` is ~49.4k LOC; tests are 180 files / 1,856 tests):

| Path | One-liner |
|---|---|
| `heber/writer/` | Ingest hot path: consumer, bronze/silver writers, contracts, DLQ fallback, compactor |
| `heber/reader/` | `HeberReader` — the canonical read interface (mypy-strict) |
| `heber/watch/` | Alert-watch service: 1,385-line consumer, 1,342-line feature extractor |
| `heber/features/pipelines/` | ~18 Gold feature pipelines (6.8k LOC, heavy duplication) |
| `heber/gold/`, `heber/gold_poller/` | Label management + EOD pipeline orchestrator |
| `heber/catalog/` | FastAPI metadata API + unused `access_control.py` |
| `heber/ops/` | Logging, metrics, reliability (dedupe/DLQ classes), lifecycle, health |
| `heber/storage/`, `versioning/`, `schema_registry/`, `quality/` | Iceberg / lakeFS / Karapace / Soda — **not wired into the data path** |
| `heber/ml/`, `universe/`, `backtest/` | ml/ live (Gold persistence); universe/ minimal; backtest/ has no live importers |
| `k8s/`, `infrastructure/` | Aspirational deploy templates (26 YAML + 7 TF files) |
| `features/` (top level) | Feast feature-store registry (27 feature views) — distinct from `heber/features/`, both live |

**Surprises.** (1) Two prior committed audits exist ([docs/repo_hygiene_audit.md](repo_hygiene_audit.md), [docs/technical_debt_audit.md](technical_debt_audit.md)) and several of their headline claims are now stale — notably "Prometheus collision blocks all tests" (suite collects 1,856 tests cleanly and sampled files pass) and the ClickHouse SQL-injection findings (`heber/hotstore/` no longer exists). (2) A complete token-based access-control system exists and is wired to nothing. (3) The CI deploy half can never execute (F-7).

## 3. Audit Report

Severity legend: **C**ritical / **H**igh / **M**edium / **L**ow. Lighter-reviewed areas: `heber/sre/`, `heber/testing/`, `alembic/`, `heber/catalog/seeds.py`, the 18 individual pipelines (3 sampled in depth), and the 192KB PRD.

### 3.1 Security

**F-1 (H) — Catalog API has no authentication and binds all interfaces.** [fact] No route in [heber/catalog/api.py](../heber/catalog/api.py) uses `Depends`/`Security` for auth — including mutating endpoints `upsert_instrument` (~line 463) and `create_backfill` (~line 502). Default bind is `0.0.0.0` ([heber/config.py:249](../heber/config.py), also `backfill_host` at line 343). Meanwhile [heber/catalog/access_control.py](../heber/catalog/access_control.py) implements `SDKToken`/`AccessControlManager` with hashing, expiry, and revocation (lines 73–245) — never imported by the API. **Why it matters:** anyone on the LAN can mutate the catalog or trigger backfill jobs. On a home network today; Critical the day this runs anywhere shared.

**F-2 (H) — Live secrets in `.env`.** [fact] `HEBER_WATCH_GATEWAY_API_KEY` and a full Discord webhook URL sit in [/.env](../.env) (lines 5, 15). The file is gitignored and not in git history (verified). **Why it matters:** webhooks are bearer credentials; any process/tool that reads the repo dir (including AI tooling — note `.aider.chat.history.md` is 3.2MB) can exfiltrate them. Rotate the webhook; treat the gateway key per its blast radius.

**F-3 (H) — Default-credential fallbacks.** [fact] `minioadmin:minioadmin` and `heber_dev_password` are fallback defaults in [docker-compose.yml](../docker-compose.yml) (MinIO ~lines 42-43, Postgres ~line 12) and [heber/config.py:184](../heber/config.py). Redis runs with no auth. **Why it matters:** dev-only today, but defaults-with-fallback is exactly the pattern that ships to staging unchanged. Pydantic `SecretStr` + no fallback for prod env is the fix.

**F-4 (M) — Security gates switched off.** [fact] Bandit is commented out in [.pre-commit-config.yaml](../.pre-commit-config.yaml) (~lines 26-35); SonarQube step is `continue-on-error: true` ([.github/workflows/ci.yaml](../.github/workflows/ci.yaml) sonar job). Trivy *is* enforced (exit-code 1) — good. **Stale prior finding:** the B608 ClickHouse f-string SQL issues cited in repo_hygiene_audit.md are gone — `heber/hotstore/` no longer exists [fact].

**F-5 (L) — Input validation on catalog params is loose.** [fact] Path/query params like `name: str`, `start_date: str` lack format constraints (api.py ~lines 229, 366, 493). SQLAlchemy parameterization blocks injection; residual risk is enumeration/path-shape abuse. [judgment] Low at current exposure; bundle with F-1.

### 3.2 Correctness & data integrity

**F-6 (H) — Bloom-filter dedupe silently drops events on false positives.** [fact] `EventConsumer` constructs `EventDeduplicator()` with no backing store ([heber/writer/consumer.py:77](../heber/writer/consumer.py)). In [heber/ops/reliability.py:150-157](../heber/ops/reliability.py), a Bloom match with no backing store is *treated as a duplicate* ("conservative") — the event is dropped, counted as processed, and ACKed ([consumer.py:349-360](../heber/writer/consumer.py)). **Why it matters:** Bloom false positives are a certainty at scale, not an edge case. At ~500k events per 1-hour rotation window (10M bits, 7 hashes), FP rate is ~2×10⁻⁴ → ~100 legitimate events/hour silently vanish from Bronze, violating the repo's own "never silently drop data" rule. The hourly rotation (reliability.py:107-128) bounds but never eliminates this. **Mitigating design note** [fact]: rotation + the previous-bloom window keep the filter sparse at low volume, so today's loss rate may be near zero — but it's unmeasured and unmonitored.

**F-7 (M) — The CI deploy pipeline is dead code; deploy-half of CI never runs.** [fact] `push`, `deploy-staging`, `deploy-prod` jobs are gated on `github.ref == 'refs/heads/main'` ([ci.yaml](../.github/workflows/ci.yaml) push/deploy jobs) but the repository's default branch is `master`. URLs are placeholders (`heber.example.com`); kubeconfig secrets target a cluster that doesn't exist. **Why it matters:** half the CI file is theater; it misleads readers about the deployment story and burns review attention. Real deployment is launchd + docker-compose.

**F-8 (M) — Unbounded response cache in the watch feature extractor.** [fact] `_response_cache` ([heber/watch/features.py:337](../heber/watch/features.py)) grows without a size cap; `_cache_set` (lines 481-484) inserts unconditionally and eviction happens only lazily inside `_cache_get` on a hit after TTL expiry (lines 469-479). The adjacent `_auth_failure_timestamps` deque *does* evict properly (lines 486-492) — the pattern is known, just not applied. **Why it matters:** memory grows with distinct `endpoint|symbol|params` keys over a long-running process. [judgment] Medium (not Critical) at one-Mac alert volumes; trivial to bound.

**F-9 (M) — Gold pipeline result-shape contract is still dual, though the counting bug is fixed.** [fact] Pipelines return either nested or flat dicts; [heber/gold_poller/service.py:440-442](../heber/gold_poller/service.py) now normalizes flat→nested before summing `total_rows` (the historical `total_rows=0` bug is fixed, contrary to a sub-audit claim — verified). **Why it matters:** every new pipeline author must know about two shapes; the orchestrator carries a permanent adapter. One enforced return type removes the trap.

**F-10 (L) — Alert parse failures log diagnostics but discard the parse exception.** [fact] [heber/watch/consumer.py:500-518](../heber/watch/consumer.py): on unparseable alerts a structured warning fires with payload keys, but the underlying exception from `_parse_alerts` isn't included, so the *reason* (encoding? schema drift?) is invisible. Not silent data loss (a prior sub-audit overstated this), but it slows diagnosis of upstream schema changes.

**F-11 (L) — `DeadLetterQueue` class is dead code kept alive by its own test.** [fact] [heber/ops/reliability.py:238-355](../heber/ops/reliability.py) is exported via `heber/ops/__init__.py` but the only consumer in the tree is `tests/test_dead_letter_queue_persistence.py`. The real DLQ is the stream + disk-fallback in `writer/dlq_fallback.py`. Misleads readers about which DLQ is live.

### 3.3 Architecture & dead weight

**F-12 (H) — Aspirational subsystems: declared, partially built, not wired.** [fact, verified by import-graph greps] `heber/storage/` (Iceberg, ~1.3k LOC incl. a 1,008-line `iceberg_catalog.py`), `heber/versioning/` (lakeFS, 520 LOC), `heber/schema_registry/` (Karapace client), plus `pyiceberg[s3]`, `lakefs`, `python-schema-registry-client` dependencies — none are imported by the live write path (`writer/*`), read path (`reader/*`), or gold poller. `heber/backtest/` has no live importers. K8s (26 YAML, incl. a writer Deployment duplicating the consumer's command) and Terraform (7 files, S3 backend, never `terraform init`-ed) are likewise unused. **Why it matters:** this is the largest tax on the repo — heavier installs, larger upgrade surface, misleading docs ("Phase 1: Iceberg" reads as current), and review attention spent on code that cannot break production because it never runs. **What it is NOT** [fact]: Feast (`heber/feast/` + top-level `features/`) and Soda (`heber/quality/`) have live call sites; `heber/ml/` is live via watch feature persistence.

**F-13 (M) — Copy-paste duplication across feature pipelines.** [fact] `_ensure_ts_available()` and `_ensure_market_instrument_key()` are byte-identical across sampled pipelines (e.g. [market_regime_features.py:33-43](../heber/features/pipelines/market_regime_features.py) vs [gex_regime_features.py:33-43](../heber/features/pipelines/gex_regime_features.py)); the lookback-window/empty-frame/OUTPUT_COLUMNS boilerplate repeats across ~18 files (6.8k LOC). A schema or invariant change must be replicated by hand N times.

**F-14 (M) — Complexity hotspots in `watch/`.** [fact] `backfill_uw_fields()` is 171 lines with two interleaved backfill strategies ([features.py:1171-1342](../heber/watch/features.py)); `AlertFeatureExtractor.extract()` chains 8 enrichments at ~114 lines (features.py:340-454); `watch/consumer.py` is 1,385 lines. [judgment] The watch service is the least cohesive module in the repo and the most likely place for the next regression.

**F-15 (M) — Broad exception handling outside the hot path.** [fact] ~139 `except Exception` sites; enrichment failures are logged-and-continued with no caller-visible signal (e.g. [features.py:763-768](../heber/watch/features.py)), so features can be silently incomplete. [judgment] The *hot path* (`writer/consumer.py`) handles this well (specific exceptions first, catch-all annotated and metered); the watch/ops periphery does not.

### 3.4 Testing

**F-16 (H) — Breadth masks thin depth on the money path.** [fact] 180 files / 1,856 tests, but: `reader/core.py` (951 LOC, the contract every trading system depends on) has one test file (`tests/test_heber_reader.py`, ~668 LOC) with no asof_join edge cases (gaps, out-of-order, tolerance boundaries); triple-barrier/availability logic in `heber/gold/labels.py` has no dedicated behavioral tests for `compute_availability_time` correctness; normalizer coercion error paths are barely exercised. Roughly 42% of test files assert on YAML/config/manifests (e.g. `test_terraform_module_sources.py` is `Path.exists()` checks; `test_k8s_hpa_probe_conformance.py` asserts manifest fields) — including conformance tests for the aspirational infra in F-12, i.e. tests guarding code that never runs. **Strength to preserve** [fact]: `test_writer_coverage.py` (1,762 LOC, 265 asserts) and the `health_monitor` conftest fixtures are genuinely good.

**F-17 (M) — Time-dependent tests.** [fact] ~101 uses of `datetime.now(UTC)`/`date.today()` in tests without freezing; e.g. `tests/test_watch_performance_verification.py:73` computes `hour - 1` and is wrong near midnight. Latent flakiness, the kind that erodes trust in CI exactly when you need it.

**F-18 (L) — Marker discipline gaps; CI runs everything.** [fact] `@pytest.mark.integration` used once; `slow` 3 times; CI runs `pytest tests/` with no marker filter ([ci.yaml](../.github/workflows/ci.yaml) test job). Mypy never runs in CI or pre-commit (disabled with ~495 errors outstanding per prior audit).

### 3.6 Performance

[judgment — flagged, not measured] Bronze/Silver writes (`gzip`, Parquet) execute synchronously inside `_process_event_once`, which runs on the event loop ([consumer.py:363, 718](../heber/writer/consumer.py)); the `asyncio.Semaphore` concurrency in `_process_stream_messages` (line 502) yields little real parallelism since the work between awaits is CPU/blocking-IO. At current single-Mac throughput this is fine; it's the first wall you'd hit scaling ingest. Not worth fixing until a measured lag appears (and consumer-lag alerting was just added — commit 658fd87 — which is the right instrument).

### 3.7 Dependencies

Healthy overall [fact]: uv.lock present and current; no known-CVE pins flagged; Dependabot config exists; Trivy enforced in CI. The issue is weight, not staleness: `pyiceberg[s3]`, `lakefs`, `python-schema-registry-client` serve unwired code (F-12), and `feast` is heavy but live.

### 3.8 Strengths (preserve these)

- **Durability discipline in the consumer** [fact]: flush-before-ACK ([consumer.py:850-865](../heber/writer/consumer.py)), disk-first DLQ with explicit "file is the record of record" reasoning (lines 166-230), pending-message recovery on startup, NOGROUP auto-recreation, bounded log-spam suppression (lines 648-686).
- **Zero-leakage is real, not aspirational** [fact]: `ts_available` predicate pushdown in reads, `write_gold` hard-fails on `ts_available < ts_event` ([reader/core.py:816-824](../heber/reader/core.py)), asof_join enforces availability via `_safe_time` (core.py:624-639).
- **Reader battle-scars encoded** [fact]: AppleDouble/tmp-file filtering with ordering-matters comments, manual Arrow schema unification across writer generations (core.py:89-266) — this is hard-won operational knowledge written down where it's used.
- Excellent structured logging/metrics, disciplined 208KB changelog, committed prior audits, detect-secrets baseline + pre-commit ruff, clean lint, and an unusually good Heber `CLAUDE.md`.

## 4. Improvement Strategy

### Theme 1 — Close the aspiration/reality gap (explains F-7, F-12, part of F-16, F-19)
**Target state:** the repo contains only code that runs plus explicitly-labeled parked work. **Principle:** unwired code is negative-value — it costs installs, review attention, and trust, and its tests defend nothing. Either wire it, or move it out (delete with git history as the archive, or an `attic/` note in docs). The CI file should describe the *actual* deployment (launchd/compose), not a fictional EKS rollout.

### Theme 2 — Guard the trust boundary you actually have (F-1..F-5)
**Target state:** no unauthenticated mutating endpoint reachable beyond localhost; no live credentials in plaintext repo files; no default-credential fallbacks outside an explicit dev mode. **Principle:** the deployment is one Mac, so the fix is cheap — bind to `127.0.0.1` or wire the already-built token auth — but the cost of *not* doing it is unbounded the day the network assumption changes.

### Theme 3 — Make data-loss impossible-or-visible on the hot path (F-6, F-8, F-10)
**Target state:** dedupe never drops an event it can't *prove* is a duplicate (Redis-backed exact check behind the Bloom prefilter), and every drop/skip path emits a metric that alerting can see. **Principle:** a lakehouse's one job is "what came in is queryable"; probabilistic structures may only ever produce false *negatives* (harmless duplicate writes), never false positives (silent loss).

### Theme 4 — Shift test investment from breadth to the money path (F-16, F-17)
**Target state:** `reader/core.py`, `writer/normalizer.py`, and `gold/labels.py` have behavioral suites covering edge cases (asof boundaries, coercion failures, label availability math); tests are time-frozen; CI separates `-m "not slow"` from a full run. **Principle:** test depth should be proportional to blast radius — these three modules feed every trading decision downstream.

### Theme 5 — Turn the dormant gates back on, incrementally (F-4, F-18)
**Target state:** CI fails on bandit (high severity), mypy passes on the already-strict module list and the list grows, sonar either gates or is removed. **Principle:** a disabled gate documents a standard the team has agreed not to meet; either meet it incrementally or delete the pretense.

### Explicitly NOT recommended (effort vs. payoff at this maturity)
- **Don't adopt Iceberg/lakeFS now.** Parquet + compactor + the reader's schema unification works at this scale. Revisit when multi-writer ACID or time-travel is a real requirement.
- **Don't build out K8s/Terraform.** One Mac + launchd is the honest architecture; keep templates only if labeled aspirational.
- **Don't chase all ~495 mypy errors or all 139 broad excepts.** Strict-module ratchet and hot-path-first narrowing respectively.
- **Don't add CORS/CSRF/rate-limiting to the catalog API** until it's exposed beyond localhost — auth + bind address covers the actual threat.
- **Don't refactor the watch consumer wholesale.** Split the two named hotspots (F-14) opportunistically when touching them.

### Definition of done (measurable)
1. `grep -r "pyiceberg\|lakefs\|schema_registry_client" heber/` returns only wired-or-deleted results; `uv sync` install footprint drops.
2. Catalog API: unauthenticated request to a mutating endpoint from a non-localhost address fails (test exists).
3. Dedupe: a forced Bloom false positive in a test results in a backing-store check, not a drop; `heber_dedupe_drops_total` metric exists and is alerted on.
4. CI: bandit + mypy(strict modules) are blocking; deploy jobs removed or runnable; full suite green in CI (it already is locally).
5. Coverage on `reader/core.py`, `writer/normalizer.py`, `gold/labels.py` ≥ 80% line / meaningful branch coverage, with frozen-time tests.
6. Zero Critical, ≤2 High findings open from this report.

### Implementation sketches — top 3

**1.2 Dedupe false-positive elimination.** Approach: keep the Bloom as a *negative cache* — `not bloom.contains(id)` still means provably-new (skip Redis). On Bloom hit, consult Redis (`SET dedupe:{event_id} 1 NX EX <ttl>` — the NX result is simultaneously the check and the register, atomic). Key steps: (a) add an async Redis-backed store satisfying `_backing_contains`/`_backing_add` — note the consumer already holds an async Redis connection, but `check()` is called from sync `_process_event_once`, so either make the dedupe check async (it's awaited two frames up) or use a second sync Redis client; (b) set TTL to ≥ stream retention so re-deliveries dedupe correctly; (c) keep `register()` post-success semantics exactly as-is (the claim/in-flight set already prevents intra-batch races, consumer.py:83-93); (d) failure mode: if Redis check errors, *process the event* (duplicate write beats silent drop) and emit a metric. Gotcha: don't register into the Bloom on drop — only on success, as today.

**1.3 Catalog auth.** Approach: FastAPI dependency `require_token(scopes)` wrapping `AccessControlManager.validate_token` (access_control.py:245); apply to mutating routes first, read routes second; token bootstrap via a CLI subcommand (`heber token create`) storing hashes in the existing Postgres catalog DB. Keep an env escape hatch `HEBER_CATALOG_AUTH_DISABLED=true` honored **only when** `environment == "dev"` (config.py:310 already has the Literal). Gotchas: the watch service and any EmpireUI calls to :8085 need tokens issued before the gate flips — grep Empire-wide for `8085`/`HEBER_CATALOG_URL` first (use Sourcegraph per monorepo CLAUDE.md); health/metrics endpoints stay unauthenticated for launchd probes.

**2.1 Aspirational-layer pruning.** Approach: decision first (Open Question 1), then one PR per subsystem to keep diffs reviewable: (storage+pyiceberg) → (versioning+lakefs) → (schema_registry+client dep) → (backtest) → (k8s+terraform+deploy-jobs+their conformance tests). For each: `grep -rn "from heber.<mod>\|import heber.<mod>"` to re-verify zero live importers, delete module + tests + deps, `uv lock`, full test run. Gotchas: `heber/quality/` (Soda) and `heber/feast/` are **live — do not remove**; `docker-compose.yml` has lakefs/apicurio services to drop in the same PRs; CHANGELOG entries per Removed-group discipline; PRD references to "Phase 1-4" need a one-line status note rather than rewriting a 192KB doc.
